# GroundTrip

> **AIの提案を、人間が根拠で選ぶ。**

GroundTripは、AIが提案した旅行プランを、根拠を確かめながら自分の判断で完成させる旅行計画アプリです。

AIによる旅程の提案に加え、施設・営業時間・移動時間の照合、予定の部分修正、旅行中の再計画、振り返りと次回の旅行への学びの反映までを、一つの体験として提供します。

**[GroundTripを開く](https://groundtrip--groundtrip.asia-east1.hosted.app/)**

※ 実際のAI・地図APIを利用する機能にはアクセス制限があります。公開環境で利用できる機能は、認証・利用権限・環境設定によって異なります。

---

## 解決したい課題

生成AIは、旅行先や希望条件から手軽に旅行プランを提案できます。しかし、その提案には、実在しない施設、確認できない営業時間、無理のある移動などが含まれる可能性があります。

もっともらしい旅程が表示されても、**なぜその予定を採用してよいのか**を利用者が判断するための根拠は、必ずしも示されません。

一方、利用者が旅行プランアプリに求めるのは、AIの間違いを探す作業ではなく、便利で実行しやすい旅行計画です。

GroundTripは、この二つの課題を同時に解決することを目指しています。

AIの提案を自動的に正解として扱うのではなく、確認できた情報と未確認の情報を区別して提示する。気になる予定は、ほかの大切な予定を守りながら部分的に変更する。そして、実際の旅行で得た経験を次回へ活かす。

**AIの誤りを探すことを目的にせず、よりよい旅行をつくる自然な操作の中に、根拠を確かめて判断する機会を組み込みます。**

## 主な機能

### 1. AIによる旅程の生成

旅行先・日付・希望条件から、Geminiが日帰り旅行の旅程を提案します。

事前に決まっている予約や訪問予定を固定予定として入力し、計画に組み込むこともできます。

生成された旅程は、訪問順や時刻が分かる路線図型のUIで表示します。この段階のAIによる提案は、まだ外部情報で照合されたものではありません。

### 2. 外部情報源による根拠の照合

利用者が根拠の確認を開始すると、AIが生成した旅程をGoogle Maps PlatformのPlaces APIとRoutes APIを使って照合します。

施設の特定、通常営業時間、移動時間などを確認し、根拠を次の状態に分けて提示します。

- **情報源と整合**：取得した情報と矛盾が見つからなかった
- **矛盾あり**：取得した情報や時間的な制約と矛盾している
- **確認できない**：必要な情報が不足している、または照合できなかった

「情報源と整合」は、実際の営業や当日の状況まで保証するものではありません。情報源・確認日時・確認できなかった事項を区別して扱います。

### 3. 固定予定を守る部分修正

旅行プランを最初から作り直さず、**変更したい予定だけ**を選んで修正できます。

Geminiが提案した代替候補に対して、Places APIによる施設情報とRoutes APIによる前後の移動を照合し、営業時間や時刻の制約を確認します。

利用者は候補の根拠や変更による影響を比較し、自分で採用するかどうかを決定します。

固定した予定は自動的に変更せず、本人の承認が完了するまで元の旅程を維持します。適用前にはサーバー側で再検証します。

### 4. 旅行中の再計画

旅行先で店舗の休業や予定の遅れなどが発生した場合も、旅行前と共通の部分修正機能を利用できます。

現地で起きたことを本人が入力すると、対象の予定について代替候補を検討し、変更による影響を確認できます。

旅行中の画面では、現在の予定や次の予定を中心に表示し、その場で必要な操作を行えるようにしています。GPSによる現在地の常時追跡は行いません。

### 5. 振り返りと学びの保存

保存した旅程について、変更履歴や本人の感想をもとに、Geminiが次回の旅行に活かせる学びの候補を生成します。

学びは自動的には確定されません。利用者が内容を確認・編集し、明示的に承認したものだけを保存します。

### 6. 次回の旅行への反映

保存した学びを選び、次の旅行の旅程生成に利用できます。

生成された旅程について、選択した学びがどの予定に反映されたとAIが説明しているかを確認できます。

これはGeminiの基盤モデルを再学習させる機能ではありません。**本人が承認した好みや条件を、次回の旅程生成に活用する仕組み**です。

## 技術スタック・アーキテクチャ

GroundTripはNext.jsを中心としたWebアプリケーションで、Firebase App Hostingを利用してGoogle Cloud上で動作します。

| 分野           | 技術                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------- |
| フロントエンド | Next.js 15、React 19、TypeScript、Tailwind CSS 4                                                   |
| バックエンド   | Next.js Route Handlers、Firebase Admin SDK                                                         |
| 生成AI         | Gemini（Google Cloud／Gemini Enterprise Agent Platform API〈旧Vertex AI API〉）、Google Gen AI SDK |
| 施設情報       | Google Maps Platform — Places API (New)                                                            |
| 経路・移動時間 | Google Maps Platform — Routes API                                                                  |
| 認証・API保護  | Firebase Authentication、Firebase App Check                                                        |
| データベース   | Cloud Firestore                                                                                    |
| ホスティング   | Firebase App Hosting                                                                               |
| データ検証     | Zod                                                                                                |
| テスト         | Vitest、Testing Library、Playwright、Firebase Emulator                                             |

![GroundTripのアーキテクチャ図](./docs/assets/groundtrip_architecture.svg)

Geminiは旅程や変更候補の生成、Places・Routesは外部情報との照合、アプリケーション側のロジックは制約検証と変更の確定を担当します。

旅程・変更履歴・承認済みの学びはFirestoreで管理し、利用者ごとの認証・認可を通してアクセスします。

## 技術的な工夫・設計思想

### AIの生成と根拠の検証を分離

GroundTripの中核となる設計は、**「提案」「照合」「制約検証」「本人承認」を別の責務として扱うこと**です。

Geminiの生成した説明を、そのまま事実の根拠としては使用しません。

施設情報や移動時間は外部APIで照合し、固定予定や時間的な制約はアプリケーション側で検証します。確認できない情報を、AIの推測で補うこともしません。

これにより、AIが得意とする柔軟な提案と、プログラムによる明示的な検証を組み合わせています。

### 変更対象を限定し、既存の旅程を保護

部分修正では、変更対象の予定を明確に特定し、固定予定や前後の移動への影響を検証します。

候補の提示だけでは元の旅程を変更せず、本人の承認後にサーバー側で再検証します。

適用時にはFirestoreのトランザクションを利用し、変更対象・旅程の版・承認記録の整合性を確認して確定します。通信結果が不明な場合も、安易な再送による二重適用を避ける設計です。

### 学びの採用も人間が決定

Geminiが生成する学びは、あくまで未承認の候補です。

本人による編集・承認を経て初めて保存対象とし、次回の旅程生成では選択された学びの所有者・承認状態・版・適用範囲をサーバー側で検証します。

学びの適用記録を伴う旅程の保存には、署名付きの証跡と保存時の再検証を使用しています。

AIの生成内容と、本人が実際に採用した内容を明確に区別します。

### 安全性と外部サービスの利用制御

APIへの入力と生成AIの出力はスキーマによって検証し、外部サービスの認証情報や署名鍵はサーバー側で扱います。

Firestoreへのクライアントからの直接アクセスはSecurity Rulesで拒否し、保存APIで本人確認と認可を行います。

また、外部APIの利用には認証・App Check・利用枠などの制御を設けています。

Google Maps Platformから取得した施設詳細・営業時間・経路情報は永続保存せず、Maps API由来の取得データについてはPlace IDのみを永続保存します。利用者が入力した予定名など、Maps API由来でないデータは区別して扱います。

## 対応範囲・制約事項

GroundTripはハッカソン期間中に開発したMVPです。主に1地域の日帰り旅行と、選択した1予定の部分修正を対象としています。

- 営業時間の照合は通常営業時間を中心とし、臨時休業や特別営業、当日の状況を保証しません。
- 移動の照合は主に徒歩を対象とし、公共交通機関の経路検索や遅延情報には対応していません。
- 路線図型UIは訪問順を示す模式図であり、実際の地理的位置・距離・縮尺を表すものではありません。
- GPSによる現在地の常時追跡や、複数日旅行の高度な最適化は対象外です。
- 外部情報の不足や制約違反によって、部分修正の候補を提示・承認できない場合があります。
- デモ用の架空データや模擬報告は、実際の照合結果や現地で発生した出来事とは区別して扱います。
- 実APIやFirestoreを利用する機能は、認証・アクセス権限・機能フラグなどの設定に依存します。コード上の実装と、公開環境での利用可否は同一ではありません。

本プロダクトは、生成AIのハルシネーションを完全に防止するものではありません。また、利用者のAIリテラシー向上を実証したものでもありません。

目指しているのは、**根拠と不確実性を利用者に伝え、AIの提案を自分で判断するための支援**です。

## 開発環境

Node.js 24.15以上の24系と、`package.json`で指定するpnpmを使用します。

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

ローカルでは <http://localhost:3000> を開きます。Firebase・Google Cloudの実APIを利用する機能には、別途環境設定とアクセス権限が必要です。

主な検証コマンドは次のとおりです。

```bash
corepack pnpm format:check
corepack pnpm lint
corepack pnpm typecheck
corepack pnpm test
corepack pnpm build
```

PlaywrightによるブラウザテストとFirebase Emulatorによる統合テストにも対応しています。詳しくはリポジトリの`docs/`内の各技術ドキュメントを参照してください。
