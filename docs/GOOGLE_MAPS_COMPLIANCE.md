# Google Maps Platform 利用条件への対応表（Issue #34）

Google Maps Platformの帰属表示・規約への記載・保存・位置情報の要件と、この版のアプリの対応状況。
公式文書の再確認日は2026-11-09。出典：Places API (New) の Policies and attributions、Google Maps Platform Terms of Service
（以下「規約」）、Service Specific Terms、Google Maps追加利用規約、Googleの利用規約。
公式資料：[Placesのポリシー](https://developers.google.com/maps/documentation/places/web-service/policies)、[Routesのポリシー](https://developers.google.com/maps/documentation/routes/policies)、[Maps Platform利用規約](https://cloud.google.com/maps-platform/terms)。詳細な調査は `docs/API_CONNECTIVITY_FINDINGS.md` §5。ここでは、要件ごとの状態と次の作業をまとめる。

状態の意味：**実装済み**＝この版のコードで満たしている／**未接続**＝部品は作ったが、画面にまだ組み込んでいない／
**対象外**＝この版のアプリはその機能を使わない（機能を足すときに再確認）／**要確認**＝チームで最終判断が必要。

## 帰属表示の書式（`GoogleMapsAttribution`）

Googleの要件どおり、次を満たす。テストで確認している（`google-maps-attribution.test.tsx`）。

- 文字は「Google Maps」から変えない。`translate="no"`、折り返さない（`white-space: nowrap`）。
- Roboto（読み込みは任意）、代替は `sans-serif`。`font-style: normal`、`font-weight: 400`、`letter-spacing: normal`。
- 文字サイズは14px（許可範囲は12〜16px）。
- 色は `gray`（#5E5E5E、既定）・`black`（#1F1F1F）・`white`（#FFFFFF）のいずれか。背景に対して4.5:1以上。
  `white` は暗い背景（#1F1F1F など）の上でだけ使う。
- 位置は、内容の**下**で、同じ枠の中（`GoogleMapsSourceBox`）。Google由来の内容は、枠線と白い背景で、
  他の内容（AIの提案・利用者の入力）と区別する。帰属を、非Google由来の内容と混ぜない。
- 常に見え、読めること。隠さない・薄くしない・クリックしないと出ない場所に置かない。

## ロゴとテキストの使い分け

公式配布のSVGを無加工で通常の出典枠に表示し、代替テキストを Google Maps とする。狭い候補比較表ではテキスト帰属を使う。ロゴは高さ18px、左右・上10px、下5pxの余白を確保する。全画面での表示領域・可視性は引き続き確認する。

## 組み込み状況

照合結果を画面に接続した版（トップ画面の「根拠を確認する」）で、次を組み込んだ。

1. **フッターのリンク**（済）：`src/app/layout.tsx` の `<main>` の後に `SiteFooter`（`LegalLinks`）を置いた。
   全ページから `/terms` とGoogleの3文書へ到達できる。ページ全体が明色テーマのため、文字色はページの文字色（#18212b）で、背景（#f3f5f7）に対して4.5:1以上。
2. **照合結果の概要**（済）：`VerificationPanel` の「照合結果あり」の内容（件数・照合日時・適用範囲）を `GoogleMapsSourceBox` で囲んだ。
   Google由来の根拠を含むときだけ囲む（根拠がない・模擬だけのときは付けない）。
3. **予定の詳細シート**（済）：`StopSheet` で、Places・Routes由来の根拠（`source.kind` が `places`／`routes`）だけを `GoogleMapsSourceBox` で囲んだ。
   公式・本人の報告・模擬の根拠は枠の外に置く。帰属は枠の下に常に見える（根拠の開閉の外側）。
4. **路線図**：訪問順の模式図。根拠の状態と移動区間の表示について、Google由来と他の情報を区別し、必要な帰属を追加する範囲は引き続き確認する。
5. **ホーム画面の一覧**（済）：照合結果の一覧は、上記2・3で扱う。
6. **模擬データ**（済）：`/demo` の模擬（`simulation`）は、Google由来ではないので、帰属を付けない（本物と区別するため。「モックデータ（架空）」の表示を維持）。
7. **確認**：枠は `min-w-0`・`overflow-wrap:anywhere`、帰属は `white-space:nowrap` で、狭い幅でも折り返されない作り。
   テストでは、枠と帰属の存在・書式・位置（`home-planner.verify.test.tsx`）を確認している。実機の320px幅とダークモードの目視は、公開前の確認事項として残る。

## 公開前の残件

次は、公開（提出・本番）の前に対応する。

1. **帰属表示の確認**：候補比較・旅程進行を含む各画面と、320px・390px幅、ダークモードを確認する。
2. ~~`/terms` への利用者向け導線~~（済）：全ページ共通のフッター。
3. **公式ロゴとテキスト帰属**：全画面で適切な表示領域と余白を確認する。
4. **後続機能の導入に伴うプライバシー説明の更新**：#44 など、送る内容・保存する内容・AIへ渡す内容が増える機能を入れるときは、
   この表と `/terms` を同じPRで更新する。
5. **照合の機能を本番で有効にする判断**：機能フラグ `TRIP_VERIFICATION_ENABLED` は既定で無効（`.env.example` では `false`）。
   Issue #29（認証・利用制限）の対応待ち。有効にするときは、`/terms` の「照合の機能を有効にした環境では」という書き方を見直す。
   画面側の保護APIは認証セッションに束縛されたBearerとApp Checkを使用する。

## 対応済みのこと（この版）

- Places・Routesの照合は、`POST /api/trips/verify` のほか、部分修正候補生成と適用前の再照合でも呼ばれる。機能フラグが `true` のときだけ動き、既定は無効（503）。
  画面からは、トップ画面で利用者が「根拠を確認する」を押したときだけ、1操作につき、このAPIが1回呼ばれる（自動では呼ばない）。
  ただし、サーバーは、予定の数に応じて、PlacesとRoutesを複数回呼ぶ（外部APIの呼び出しは1回ではない）。
  機能フラグが無効の環境では、画面に「根拠の確認は現在利用できません」と表示する。そのため、`/terms` は「照合の機能を有効にした環境では」と条件付きで書いている。
  機能フラグを本番で有効にするときは、この書き方を見直す。
- Google由来の値は保存しない（Place IDを除く）。名称・住所・営業時間・価格は処理中にだけ使う。
- 位置情報を取得しない。常時追跡もしない。
- 写真・レビュー・AI要約を使わない。
- Googleの内容を、AIの学習・改善に使わない。
- `/terms` には、この版が実際にしていること（事実）だけを書く。機能（保存・認証・位置情報など）を足すときは、
  この表と `/terms` を、同じPRで更新する。
