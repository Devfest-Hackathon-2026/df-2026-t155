# Google Maps Platform 利用条件への対応表（Issue #34）

Google Maps Platformの帰属表示・規約への記載・保存・位置情報の要件と、この版のアプリの対応状況。
公式文書の確認日は2026-11-07。出典：Places API (New) の Policies and attributions、Google Maps Platform Terms of Service
（以下「規約」）、Service Specific Terms、Google Maps追加利用規約、Googleの利用規約。
詳細な調査は `docs/API_CONNECTIVITY_FINDINGS.md` §5。ここでは、要件ごとの状態と次の作業をまとめる。

状態の意味：**実装済み**＝この版のコードで満たしている／**未接続**＝部品は作ったが、画面にまだ組み込んでいない／
**対象外**＝この版のアプリはその機能を使わない（機能を足すときに再確認）／**要確認**＝チームで最終判断が必要。

## 帰属表示の書式（`GoogleMapsAttribution`）

Googleの要件どおり、次を満たす。テストで確認している（`google-maps-attribution.test.tsx`）。

- 文字は「Google Maps」から変えない。`translate="no"`、折り返さない（`white-space: nowrap`）。
- Roboto（読み込みは任意）、代替は `sans-serif`。`font-style: normal`、`font-weight: 400`、`letter-spacing: normal`。
- 文字サイズは14px（許可範囲は12〜16px）。
- 色は `gray`（#5E5E5E、既定）・`black`（#1F1F1F）・`white`（#FFFFFF）のいずれか。背景に対して4.5:1以上。
  `white` は暗い背景（#1F1F1F など）の上でだけ使う。
- 位置は、内容の**下**で、同じ枠の中（`GoogleMapsSourceBox`）。Google由来の内容は、枠線と白い背景で、
  他の内容（AIの提案・利用者の入力）と区別する。帰属を、非Google由来の内容と混ぜない。
- 常に見え、読めること。隠さない・薄くしない・クリックしないと出ない場所に置かない。

## ロゴへの移行

今回はテキスト「Google Maps」で実装した。ロゴが望ましいので、移行するときは次の順で行う。

1. Googleが提供する公式のロゴ素材と、利用ガイドライン（余白・最小サイズ・背景色）を入手する。独自に描き直さない。
2. `GoogleMapsAttribution` の中身だけを、ロゴ（`next/image` または inline SVG。代替テキスト「Google Maps」）に差し替える。
   呼び出し側（`GoogleMapsSourceBox`、画面）は変えない。
3. 表示領域が狭い場合は、テキストへ戻せるようにする（要件上、狭い領域ではテキストでよい）。
4. テストを、ロゴ向けに更新する（代替テキスト、最小サイズ、背景に対する見え方）。

## 組み込みの場所と手順（残件）

PR #38 は main にマージ済み。ただし、以下の組み込みはまだ行っていない（`src/app/layout.tsx` に `<footer>` と `LegalLinks` はない）。
次の順で行う。

1. **フッターのリンク**（`src/app/layout.tsx`）：`<main>` の後に `<footer>` を置き、`LegalLinks` を入れる。
   全ページから `/terms` とGoogleの3文書へ到達できるようにする。文字色は、ページ外側の配色（ダークモード）でも
   読めるようにする（コントラスト4.5:1以上）。
2. **検証結果の表示**（`src/features/trip-map/evidence-badge.tsx` の `EvidenceDetail`）：Places・Routes由来の内容
   （名称・営業時間・所要時間など）を出すブロックを `GoogleMapsSourceBox` で囲む。「情報源」の行のうち、
   Google由来のものだけを囲み、AIの提案文や本人の入力は枠の外に置く。
3. **路線図**（`src/features/trip-map/trip-route-view.tsx`、`stop-sheet.tsx`）：駅やチケットに、Places由来の名称・営業時間を
   出す箇所を洗い出し、同じ視覚的なまとまりごとに `GoogleMapsSourceBox`（または、狭い場所では、内容の下に
   `GoogleMapsAttribution`）を置く。1つの画面に複数のまとまりがあるときは、まとまりごとに帰属が必要かを確認する。
4. **ホーム画面**（`src/features/home/home-planner.tsx`）：照合結果を一覧で出す場合は、同様に囲む。
5. **確認**：モバイル幅（320px）で、帰属が折り返されず、はみ出さないこと。ダークモードでも、枠の中が白地・濃い文字で
   読めること。モック（デモ用の架空データ）の表示は、Google由来ではないので、帰属を付けない（本物と区別するため）。

## 公開前の残件

次の4つは、公開（提出・本番）の前に対応する。いずれも、この版では未対応。

1. **帰属表示の組み込み**：Google由来の内容を表示する画面（検証結果・路線図・ホーム画面）へ、`GoogleMapsSourceBox` を組み込む（上の「組み込みの場所と手順」）。
   PR #38 はマージ済みだが、組み込みは未実施。現在の画面には、Google由来の内容は出していない（照合の結果は画面に接続していない）。
2. **`/terms` への利用者向け導線**：フッター等から `/terms` へ到達できるようにする（上の手順1）。
3. **表示領域に応じた、公式ロゴとテキスト帰属の使い分け**：ロゴへの移行（上記）の手順で行う。狭い領域はテキストのままにする。
4. **後続機能の導入に伴うプライバシー説明の更新**：#44 など、送る内容・保存する内容・AIへ渡す内容が増える機能を入れるときは、
   この表と `/terms` を同じPRで更新する。

機能フラグ `TRIP_VERIFICATION_ENABLED` は既定で無効（`.env.example` では `false`）。
本番で有効にするかは、Issue #29 の対応待ち。

## 対応済みのこと（この版）

- Places・Routesの照合は、`POST /api/trips/verify` からだけ呼ばれる。機能フラグが `true` のときだけ動き、既定は無効（503）。
  画面からはまだ呼ばれていない。そのため、`/terms` は「照合の機能を有効にした環境では」と条件付きで書いている。
  機能フラグを本番で有効にするときは、この書き方を見直す。
- Google由来の値は保存しない（Place IDを除く）。名称・住所・営業時間・価格は処理中にだけ使う。
- 位置情報を取得しない。常時追跡もしない。
- 写真・レビュー・AI要約を使わない。
- Googleの内容を、AIの学習・改善に使わない。
- `/terms` には、この版が実際にしていること（事実）だけを書く。機能（保存・認証・位置情報など）を足すときは、
  この表と `/terms` を、同じPRで更新する。
