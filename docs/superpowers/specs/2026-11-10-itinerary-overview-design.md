# 旅行前の路線図・情報整理

## 合意と方針

ユーザーの「次進めて」を受け、候補比較（#84）の次として旅行前の路線図を改善する。共有HTML（Figma改善版と同内容）の01を参考に、時刻・場所・固定・根拠の状態を把握しやすくする。

採用するのは既存路線図へのコンパクトな概要追加と予定カードの情報整理。全面作り直しは認証・復旧・詳細シートの再実装を伴うため避ける。旅行中の改修、APIやデータモデルの追加は別段階とする。

## 表示と操作

- TripRouteViewの路線図の直前に、紙面風の「旅程の根拠」概要を置く。固定予定数と、付いているGoogle Maps由来の根拠の内訳を表示する。
- Mapsの集計には既存summarizeVerificationを再利用し、情報源と整合・矛盾あり・確認できないを区別する。単位は根拠の件数であり予定数ではない。根拠数から旅程全体の安全・全項目の照合完了を断定しない。
- Google由来が0件なら「現在の旅程にはGoogle Mapsの照合結果がありません」とする。過去に一度も照合していないとは断定しない。本人報告・公式情報・模擬根拠はGoogleの件数に加えず、別の根拠として扱う。Google由来情報には既存の帰属部品を使用する。
- evidenceが空の予定数は別単位で「根拠なしの予定」と示す。情報を取得して確認できなかった根拠と混同しない。
- 「予定ごとの根拠を見る」を展開すると、各予定の時刻・名前・固定・根拠件数が分かり、既存詳細シートへ進める。新しい照合・承認・保存操作は作らない。
- 概要から詳細シートを開いた場合、閉じた後は起点ボタンへフォーカスを戻す。起点が消えていれば既存の予定ボタン/一覧への退避を使う。路線図から開く操作は既存のまま。
- 通常の予定カードにも滞在時間を見える形で加える。予定時刻であり実測ではない。既存の読み上げ名・固定・種別・移動区間の判定を維持する。
- 紙・オレンジの路線・青い未承認候補の役割を保つ。模擬表示と模式図の説明を残し、概要に大きな説明を増やしすぎない。

## 境界と検証

API、認証、App Check、Firestore、適用中/結果不明の制御、固定切替の意味を変更しない。新しい画像・外部フォント・ライブラリは不要。本番設定と実APIに触れない。

320px/390pxで概要・展開・詳細シートと閉じた後のフォーカスを確認する。集計のソース分離、Google根拠0、空の根拠、混在する状態を重要テストとし、既存の単体/回帰テストを再利用する。
